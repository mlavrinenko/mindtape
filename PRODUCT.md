# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Typst content rendered by tola 0.7.1 to static HTML, with hand-written CSS in `www/assets/styles/` and small inline scripts. The existing stack is kept; the redesign changes the visual world, not the build system.

## Users

- **Engineers and tech leads** who keep a backlog in the same repository as the code, and want it readable, reviewable and versioned beside it.
- **AI coding agents** that file, read and flip tasks through `mt`, and need stable files, JSON output and actionable refusals.
- **Newcomers evaluating the tool** who need to understand the mechanism before installing anything.

The job: capture work in a form a person can read, an agent can parse, and a rule can check, so the backlog stays trustworthy without a separate service.

## Product Purpose

Mindtape is a file-based task tracker. One task is one Typst file. Every `mt` command evaluates those files, so the task list, the task document and the rules that check them all come from the same plain text. Success means a team can read its backlog, trust it, and act on it from a clone.

## Positioning

No daemon, no database, no index: tasks are files in your repo, typed and checked by your own config. The same file is both the data and the document, and the rules live in `.mindtape/config.toml` rather than in the tool's code. A hosted issue tracker cannot truthfully copy that mechanism.

## Operating Context

The CLI is `mt`; configuration is `.mindtape/config.toml`; a project's tasks live under a configured root. People read the docs before adopting, while setting up a project, and later for lookup of a command, config key, recipe or DSL field. Agents read the same pages, often through the Markdown copy. The site is used in light and dark, on desktop and phone, with search.

## Capabilities and Constraints

- The docs site covers Start, Recipes, Tasks, Fields, Checks, Reference and Integrate. Routes and page content stay.
- The site must keep: the logo, the green accent, dark mode, search (Pagefind, production builds), the mobile nav drawer, copy-page-as-Markdown, the on-this-page index, working keyboard navigation and reduced-motion support.
- Content is authored in Typst and generated by `just docs::gen`; captures in `www/generated/` are real command output and must not be replaced by invented output.
- No image-generation tool is available. Comps are authored as full-fidelity HTML/CSS and screenshotted for measurement.
- No analytics, no tracking, no external claims.

## Brand Commitments

- The name is **Mindtape**, set from `tola.toml`, never retyped in prose.
- The cassette-and-tape logo is the mark. It stays monochrome in silhouette and is tinted with the accent.
- The green accent stays: `#12805a` in light mode, `#45d0a0` in dark mode.
- Voice: plain, technical, direct. It explains a mechanism and shows real output; it does not sell, hype or use playful gimmicks.
- The terminal is one material the product produces, not a costume the whole interface wears.

## Evidence on Hand

- `README.md` and the docs pages carry the product's own explanations and real code.
- `www/generated/` holds captured `mt` output, task slices, diagrams and the typeset task card.
- `examples/api-service/` is a working sample backlog; `examples/large/` is a 2000-task benchmark.
- There are no customer logos, testimonials or usage benchmarks; the redesign must not invent any.

## Product Principles

1. **The file is the truth.** Every surface should make the plain file feel like the source, not a preview of a hidden system.
2. **Show the mechanism.** A real task, a real refusal and a real command teach faster than an abstract feature list.
3. **Rules are legible.** Checks, statuses and recipes should read as something a reader can inspect and change.
4. **One surface for people and agents.** Human-readable and machine-readable are the same goal seen twice.
5. **Quiet scaffolding, strong structure.** The navigation and chrome should disappear into clear reading order.

## Accessibility & Inclusion

Meet WCAG 2.2 AA for contrast, focus visibility and keyboard operation. Preserve semantic landmarks, screen-reader labels, the skip-free reading order and `prefers-reduced-motion` behavior. Do not encode meaning in color alone; status hues always carry a text label or glyph.
