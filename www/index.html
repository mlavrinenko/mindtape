MindTape

A daemon-free, file-based task tracker powered by Typst.
One task per .typ file, living right next to the code it tracks.

How It Works

Write .typ files

One task per file via #show: task.with(...). Status, priority (a raw int or a scoring framework like ice(...)), tags, dates — all plain Typst, right where your project lives.

MindTape evaluates live

No daemon, no database, no global index. Each command re-evaluates the configured roots with the Typst compiler.

Query & validate via CLI

Filter with an expression language. Output as table, JSON, or CSV. Validate every task against .mindtape/config.toml.

🧠🧠🧠 🧠🧠🧠 🧠🧠🧠

Why Typst?

{ }

Structured

Typed variables, static checking, no ambiguity. Your task data is validated at the source — not after the fact.

#

Composable

Files import each other with #import. Reuse task templates, share definitions, build on existing work.

.typ

Human-readable

Plain text files you can read, diff, and version-control. No lock-in, no binary blobs, no cloud dependency.

🧠🧠🧠 🧠🧠🧠 🧠🧠🧠

Features

🔍

Rich Filtering

Filter by status, priority, tags, due and start dates, estimate, or file — full boolean expressions with full-text search.

📋

Multiple Formats

Output tasks as an aligned table, pretty JSON, or CSV.

✅

Config-driven Validation

mindtape check validates every task against your config: enum values, required fields, numeric bounds, task links, and dependency cycles.

❄️

Reproducible

A Nix flake pins the whole toolchain; CI and your shell run the exact same checks.

Installation

# Run straight from the flake:
nix run github:mlavrinenko/mindtape -- --help

# Or enter the dev shell to hack on it:
nix develop github:mlavrinenko/mindtape
git clone https://github.com/mlavrinenko/mindtape.git
cd mindtape
cargo build --release
# Install the Typst library (once per machine)
./target/release/mindtape install-lib
# Scaffold a project (once per project)
./target/release/mindtape init
